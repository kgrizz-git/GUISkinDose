# Documentation Help Harness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a maintainable documentation and GUI-help harness that catches stale paths, missing in-app help, undocumented user-facing features, and inconsistent terminology before release.

**Architecture:** Add small, machine-readable metadata files for GUI help coverage, UI copy, glossary terms, and feature-to-documentation traceability. Keep checks lightweight and deterministic in `scripts/`, start new policy as advisory where it could create noise, and promote only low-noise validations to pre-commit/CI after the repository has baseline metadata.

**Tech Stack:** Python standard library, pytest, existing pre-commit hooks, Markdown source files under `dev-docs/` and `docs/source/gui_help/`, NiceGUI UI source under `src/mypyskindose/gui/`.

---

## Scope

This plan replaces the archived brainstorm at `dev-docs/plans/archive/DOCUMENTATION_AND_HELP_INFRASTRUCTURE_BRAINSTORM.md`.

Included:

- Detect stale repo-relative paths in Markdown links, backtick code spans, and clear prose path mentions.
- Create a GUI help registry so each user-facing tab or workflow has a declared help page.
- Add static tests that every registered help page exists in `docs/source/gui_help/`, is mirrored to `src/mypyskindose/gui/help/`, and is referenced by GUI code.
- Introduce a UI copy catalog for high-risk explanatory text: tooltips, warnings, help-button titles, and short field help.
- Add a glossary file and lint obvious inconsistent terminology.
- Add a feature-to-documentation matrix with an advisory doc-impact script.
- Add executable documentation checks for coordinate conventions and settings/help coverage where code already has stable facts.

Deferred to separate backlog items: screenshot baseline tests, in-app inaccurate-help feedback, per-run processing narratives, generated adapter diagrams, and release PR checklist generation.

## Policy Decisions

- `docs/source/gui_help/` remains the source of truth for help pages. `src/mypyskindose/gui/help/` remains generated by `scripts/sync_gui_help.py`.
- New static checks must parse source text or metadata. Do not import NiceGUI tabs in harness scripts because importing UI code can trigger runtime dependencies and side effects.
- Checks that inspect repo-wide feature impact start advisory by default. They may fail only for malformed metadata, missing referenced files, or explicit `--strict`.
- Avoid forcing every label into a catalog in the first pass. Catalog high-risk explanatory copy first, then grow coverage opportunistically.
- Metadata files use JSON and all checkers parse them with standard-library `json.loads()`. Do not add a YAML dependency or a custom YAML parser for this harness.

- [ ] **Step 2: Implement path span extraction**

Add a `PathReference` dataclass with `source`, `line_number`, `target`, `context`, and `message`.

Use two extractors:

- Backtick extractor for code spans containing `/` and ending in a known repository extension or directory segment.
- Prose extractor for tokens matching `(?:AGENTS|CHANGELOG|DESIGN|README)\.md`, `dev-docs/...`, `docs/source/...`, `src/...`, `tests/...`, or `scripts/...`.

Normalize trailing punctuation: `.`, `,`, `;`, `:`, `)`.

- [ ] **Step 3: Resolve and report stale path references**

Reuse `split_link_target()` and `resolve_relative_link()` for relative paths. Add archive suggestions by checking whether a missing `dev-docs/plans/<name>` exists under `dev-docs/plans/archive/<name>`.

Expected output format:

```text
dev-docs/TO_DO.md:91: stale path `dev-docs/plans/example.md`; archived candidate: dev-docs/plans/archive/example.md
```

- [ ] **Step 4: Wire into `main()`**

Broken path references should fail like broken links. Add `--no-path-reference-scan` only if needed for emergency bypass.
